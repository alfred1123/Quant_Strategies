| 22 | **INST versioning** | `PRODUCT` uses soft-versioning (`PRODUCT_VID` + `IS_CURRENT_IND`). `PRODUCT_XREF` uses version rows plus transaction-time windows (`PRODUCT_XREF_VID`, `TRANSACT_FROM_TS`, `TRANSACT_TO_TS`). `PRODUCT_GRP` and `PRODUCT_GRP_MEMBER` do **not** — hierarchy versioning is impractical; `PRODUCT_GRP` uses `UPDATED_AT` for admin edits, `PRODUCT_GRP_MEMBER` is add/remove only. | database.md |
| 23 | **PRODUCT_XREF population** | Long-term design is semi-automatic vendor import with proposal/approval before writing `INST.PRODUCT_XREF`. Until that workflow exists, admin/bootstrap population may be done directly in the DB. Application write paths still use stored procedures. | separate-underlying.md |
| 24 | **DbGateway + schema repos (strict-OOP)** | `quant/shared/db.py` provides the `DbGateway` base class — the **only** module in `quant/` that imports `psycopg`. Subclasses (`InstrumentCache`, `BacktestCache`, `WorkerRepo`, `AuthRepo`, `RefDataPublisher`) call `_call_get` / `_call_write` / `_query` and never touch `psycopg` directly. Connection mode is set at construction via `persistent: bool` — `False` (default) opens a short-lived connection per call; `True` holds one long-lived connection (used by the two cache classes) and exposes an idempotent `close()`. No `conn=` kwargs and no `_open_conn()` helper — the gateway fully encapsulates connection lifecycle. `RefDataCache` (in-process) was **superseded** by Redis-backed `RedisRefData` (see decision #31). | pipeline.md |
| 25 | **Drop TICKER_MAPPING** | `REFDATA.TICKER_MAPPING` dropped via Liquibase changeset `116-refdata-drop-ticker-mapping`. Functionality replaced by `INST.PRODUCT_XREF`. No Python code referenced it. | database.md |
| 26 | **Backtest queue infrastructure** | ~~TypeScript coordinator + Python worker~~ — **superseded by decision #32**. Original rationale (TS for SSE / type-sharing with frontend) was outweighed by the operational cost of running two services and the duplicated DB-access layer. | backtest-queue.md |

| 30 | **Optional local Postgres for dev** | Decision #17 (SSM tunnel only) is now the **default**, not the only option. Opt-in `DB_TARGET=local` switches dev to a host-side Postgres 17 (port 5432) populated by `./scripts/dbctl.sh dump|restore` from Aurora. When set, `./scripts/appctl.sh dev start` also brings up Redis + the Python queue worker via `docker-compose.dev.yml`. FastAPI publishes REFDATA into Redis on boot — start the API (or `docker compose up api`) before the worker so dropdowns populate. Teammates without local PG leave `DB_TARGET` unset and use the SSM tunnel. | dev-vs-prod.md |
| 31 | **`refdata/` separated from `data/`** | `quant/refdata/` (Redis-backed config dimensions) is a sibling package of `quant/data/` (Postgres-backed time-series + instrument facts), not a subfolder. Different storage tier (Redis vs Postgres), different read/write asymmetry (many readers / one publisher vs per-call read+write), different freshness model (Redis `refdata:version` stamp checked on every `get()` vs no version stamp). Boot ordering is enforced by `quant/refdata/bundle.py::DataCaches`, which constructs `RedisRefData` first, then `InstrumentCache` and `BacktestCache` (which depend on REFDATA for `APP_ID` / `APP_METRIC_ID` lookups). `quant/refdata/publisher.py` is the **only** Postgres-touching file in `refdata/` and the **only** writer of `refdata:*` Redis keys (replaces the former TS coordinator's `coordinator/src/refdata/cache.ts`). Invoked from FastAPI's `lifespan` and the admin endpoint `POST /api/v1/refdata/refresh`. | bundle.py / publisher.py / reader.py |
| 32 | **Queue collapsed into Python** | **Done.** TypeScript coordinator removed. FastAPI serves `/api/v1/jobs/*` (enqueue, list, cancel, SSE). Long-lived `quant.queue.worker_loop` claims jobs via Redis wake + `SP_INS_QUEUE`. `coordinator/` deleted. | backtest-queue.md, `quant/api/routers/jobs.py` |
